## 执行摘要

样本是一个 64 位 Windows GUI 程序，未发现 Authenticode 签名，静态导入表完整可读，壳检测结果为“Not packed (likely)”。程序内置约 14.4 MB 的高熵资源区，并包含名为 `CONFIG` 和 `PAYLOAD` 的资源线索；配置字符串指向 `www.dadadadanb.top:443` 及多个会话、程序信息和安全上报接口，同时出现 AES-GCM/HKDF、API key、DPAPI 和完整性校验字段。静态证据说明它具备联网、配置/载荷解密、机器信息读取和反调试能力，但不能单凭这些 API 证明恶意。经用户明确确认后，样本在宿主机真实启动，PID `32016` 持续运行满 60 秒并被终止；在这段时间内没有观察到样本子进程、样本目录文件变化或 Run/RunOnce 持久化变化。由于 `pktmon` 驱动不可用，本次没有运行时网络证据，因此域名和接口仍属于静态待验证 IOC。

## 5. 结论与下一步

这次不是“理论运行”：`11111.exe` 已在用户确认后于宿主机真实启动，并在 60 秒后由 REVLab 清理。能确认的事实是它具备网络/密码学/本地配置处理能力、携带高熵资源和服务配置线索，并在本次无输入运行中保持 GUI 进程；不能确认的事实包括运行时是否访问域名、是否提交凭据、是否解密载荷以及完整业务行为。

推荐下一轮只做两件事：一是用管理员权限修复 `pktmon` 或接入等价的本机连接采集，二是在明确的测试账号/无敏感凭据前提下，用 API/文件 I/O 跟踪观察登录、配置和载荷路径。不要把样本中的 API key、master key 或 xor key 用于任何外部请求。
